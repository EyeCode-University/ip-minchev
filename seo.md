## 2. Найденные проблемы

### P0 — блокирующие

#### 2.1. Галерея полностью отсутствует в HTML для робота

[src/components/Gallery/GalleryDynamic.js](src/components/Gallery/GalleryDynamic.js) грузит галерею через `dynamic(..., { ssr: false })`.

Последствие: в серверном HTML нет ни `<h2>Наша продукция</h2>`, ни 22 названий изделий,
ни alt-текстов, ни имён заводов-заказчиков. Это самый коммерчески ценный контент сайта:
«гидроцилиндр», «шарнир водоохлаждаемый», «плунжерный цилиндр Ø360 × L3600»,
«МНЛЗ», «СТАН 3000», «Азовсталь», «Запорожсталь». Googlebot дорендерит JS с задержкой
и не гарантированно, Яндекс — существенно хуже.

Причина `ssr: false` — расхождение гидратации из-за `FadeIn` (motion, `initial={{ opacity: 0 }}`).
Лечить нужно причину: контент обязан быть в DOM всегда, анимация — только визуальный слой.

#### 2.2. Нет `metadataBase`

Next не может построить абсолютные URL → `og:image` и canonical нерабочие.

#### 2.3. Нет `robots.txt` и `sitemap.xml`

Файлов `src/app/robots.js` и `src/app/sitemap.js` не существует.

#### 2.4. Нет `og:image`

Ссылка на сайт в Telegram / WhatsApp / письме разворачивается голым текстом.
В B2B ссылку пересылают снабженцу или главному механику — это прямая потеря кликов.

#### 2.5. Разнобой в наименовании компании

Три разных сущности в коде:

| Где | Значение |
|---|---|
| [constants.js](src/lib/constants.js) `COMPANY.name` | `gidromashprom` |
| [privacy.js](src/lib/privacy.js) `OPERATOR.name` | `Торговый представитель Минчева Э.Р.` |
| CLAUDE.md | `ИП Минчев Р.М.` |

Для брендового поиска и E-E-A-T нужно одно официальное наименование + один бренд,
консистентно в `title`, футере, Schema.org и карточке Яндекс.Бизнес.

#### 2.6. Домен не зафиксирован

В [SETUP-SERVER.md](SETUP-SERVER.md#L289) `server_name ВАШ_ДОМЕН.ru`.
Домен нужно определить **до** начала индексации: переезд обнуляет накопленные сигналы.

### P1 — влияют на объём трафика

#### 2.7. Нет микроразметки Schema.org

JSON-LD отсутствует полностью (`grep 'application/ld+json'` — пусто).

#### 2.8. Архитектура «одна страница = один запросный кластер»

Весь семантический вес сжат в один URL. Невозможно одновременно ранжироваться по
`изготовление гидроцилиндров на заказ`, `арматура высокого давления Ру250`,

Данные для посадочных страниц уже структурированы в [constants.js](src/lib/constants.js):
`EQUIPMENT_LIST`, `MACHINE_FLEET`, `MACHINING_CAPABILITIES`, `GALLERY_ITEMS`.

#### 2.9. Core Web Vitals

- `ReactorModel` — WebGL на OGL в Hero, монтируется синхронно, занимает главный поток
  ровно в момент LCP. `prefers-reduced-motion` учтён, но это не про производительность.
- `public/assets/generated_images` — 43 МБ PNG. В [next.config.mjs](next.config.mjs)
  не заданы `images.formats` → нет AVIF.
- `public/assets/videos/vid.MP4` — 19 МБ, в превью галереи `preload="metadata"`.

#### 2.10. NAP отсутствует в HTML главной

Адрес, город, реквизиты есть только на правовых страницах.
В [Contacts.js](src/components/Contacts/Contacts.js) и [Footer.js](src/components/Footer/Footer.js)
нет адреса, ИНН/ОГРНИП и режима работы — обязательный блок для коммерческого
и локального ранжирования.

#### Что именно сделано

**FadeIn переписан без motion**

[FadeIn.js](src/components/FadeIn.js) + новый [FadeIn.module.css](src/components/FadeIn.module.css).
Появление при скролле теперь делает `IntersectionObserver`, который вешает класс
`.visible`, а сам переход — CSS. API компонента не изменился (`delay`, `y`,
`duration`, `className`), все 15 мест использования работают без правок.

Почему так: motion подставлял инлайновые стили на клиенте иначе, чем в серверном
HTML, и из-за этого галерею держали на `dynamic(..., { ssr: false })`. Причину
убрали — исчез и повод отключать SSR. Побочный эффект: `motion` больше не
тянется ради обычного «проявления», остался только в лайтбоксе (`AnimatePresence`).

Оговорка: при выключенном JS блоки останутся прозрачными. Для поиска это
неважно — текст присутствует в HTML, а именно он и индексируется; и Google,
и Яндекс исполняют JS. Для `prefers-reduced-motion` контент показывается сразу.

**Галерея**

- Удалён [GalleryDynamic.js](src/components/Gallery/GalleryDynamic.js),
  [page.js](src/app/page.js) импортирует `Gallery` напрямую.
- В [Gallery.js](src/components/Gallery/Gallery.js) добавлен полный перечень
  изделий: в сетке по-прежнему 4 карточки, остальные 19 позиций присутствуют
  текстом в визуально скрытом списке (`.fullList`, стандартный visually-hidden
  через `clip-path`, а не `display: none` — блок остаётся в дереве доступности).
  Намеренно без `<Image>`: два десятка лишних изображений в DOM утянули бы LCP.

**Секция «Возможности» — та же болезнь, найдена по ходу**

Станочный парк (14 станков с моделями: 16К20, 1М63, SRK 100, 2А636 …) и 6 из 9
техвозможностей рендерились только после клика «Подробнее» — в HTML их не было
вообще. Это самый узкоспециализированный и уникальный контент сайта.

Теперь [Capabilities.js](src/components/Capabilities/Capabilities.js) рендерит
их всегда, а свёрнутое состояние выражено атрибутом `hidden`. Контент за
аккордеонами Google индексирует нормально (официальная позиция с перехода на
mobile-first), при этом на экране ничего не меняется. В
[globals.css](src/app/globals.css) добавлено `[hidden] { display: none !important }` —
без этого `.card` со своим `display: flex` перебил бы атрибут.

#### Что именно сделано

**3D-модель больше не мешает первому экрану**

[Hero.js](src/components/Hero/Hero.js): `ReactorModel` подключается через
`dynamic(..., { ssr: false })` и монтируется в `requestIdleCallback` уже после
первой отрисовки (запасной путь — `setTimeout` для Safari до 18-й версии).

Сборка сцены на OGL и компиляция шейдеров занимали главный поток ровно тогда,
когда браузер должен был показать заголовок. Проверено: в стартовых чанках
главной страницы кода OGL больше нет — он приезжает отдельным файлом позже.

**Изображения**

В [next.config.mjs](next.config.mjs) добавлены `images.formats`
(`avif`, `webp`) и `minimumCacheTTL` на год вместо дефолтных 60 секунд.

Замер на реальном файле галереи (`slide-item (1).png`, исходник 2 562 828 байт):

| Ширина | Формат | Размер |
|---|---|---|
| 640 | AVIF | 26 177 байт |
| 640 | WebP | 89 516 байт |
| 640 | PNG | 118 182 байт |
| 1080 | AVIF | 54 201 байт |
| 1080 | WebP | 239 770 байт |

То есть карточка галереи на телефоне весит 26 КБ вместо 2,5 МБ исходника
и втрое меньше, чем в WebP до этой правки.

**Кеширование статики**

Next отдаёт файлы из `public/` без заголовков кеширования — видео и
неоптимизированные ассеты качались заново при каждом визите. Добавлен
`headers()` для `/assets/:path*`:
`public, max-age=86400, stale-while-revalidate=604800`. Не `immutable` —
имена файлов не хешируются, и замена картинки должна доезжать до посетителей.

**Проверка**

```
npm run build   → ✓, 13 маршрутов
npm run lint    → 0 ошибок
npm test        → 36/36 passed
```

Ответы сервера: `/_next/image` отдаёт `Content-Type: image/avif`,
`/assets/videos/vid.MP4` — заданный `Cache-Control`, в стартовых чанках
главной OGL отсутствует.

#### Что не сделано и почему

Видео `vid.MP4` (19 МБ) осталось на `preload="metadata"`. Чтобы поставить
`preload="none"`, нужен кадр-постер, иначе карточка в галерее будет пустой.
В окружении нет ffmpeg. Когда появится:

```bash
ffmpeg -i public/assets/videos/vid.MP4 -vframes 1 -q:v 3 public/assets/videos/vid-poster.jpg
```

затем в [Gallery.js](src/components/Gallery/Gallery.js) добавить
`poster="/assets/videos/vid-poster.jpg"` и заменить `preload="metadata"`
на `preload="none"`.
